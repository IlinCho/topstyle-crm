# TopStyle CRM

Самостоятелен онлайн магазин + админ панел (CRM), изграден от нулата по образец на текущия topstyle.bg (PrestaShop). Съдържа:

- **Витрина** (`/`) — начало, категории, продуктова страница с избор на размер, количка, поръчка с наложен платеж.
- **Админ панел** (`/admin`) — вход, табло, продукти (създаване/редакция/изтриване, размери и наличност, снимка), категории, поръчки.
- **База данни** чрез Prisma ORM — локално SQLite (нулева настройка), готово да се превключи на Postgres за Vercel.
- **166 реални продукта**, заредени от topstyle.bg (виж по-долу), с преработени, описателни имена вместо generic "тениска" / "бански" и т.н.

## 1. Локално стартиране

```bash
npm install
npm run db:push      # създава SQLite базата по схемата
npm run db:seed      # зарежда категориите + 166-те продукта + създава admin акаунт
npm run dev
```

Отвори http://localhost:3000 за магазина и http://localhost:3000/admin за админ панела.

Данни за първия админ акаунт се задават чрез `.env` (копирай `.env.example` → `.env`):

```
ADMIN_EMAIL="admin@topstyle.bg"
ADMIN_PASSWORD="избери-силна-парола"
SESSION_SECRET="дълъг-случаен-стринг"
```

(`npm run db:seed` създава акаунта само ако не съществува вече.)

## 2. Deploy във Vercel

SQLite файлът работи чудесно локално, но Vercel е serverless и няма постоянна файлова система — затова за продукция трябва Postgres:

1. Създай безплатна Postgres база — най-лесно през **Vercel → Storage → Create Database → Postgres** (или neon.tech / supabase, също работят с Prisma).
2. В `prisma/schema.prisma` смени:
   ```prisma
   datasource db {
     provider = "postgresql"   // беше "sqlite"
     url      = env("DATABASE_URL")
   }
   ```
3. Качи проекта в GitHub и го импортирай във Vercel (или `vercel deploy` през CLI-то).
4. В Vercel → Settings → Environment Variables добави: `DATABASE_URL` (от стъпка 1), `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
5. Приложи схемата към продукционната база и я зареди с продуктите:
   ```bash
   DATABASE_URL="<production-url>" npx prisma db push
   DATABASE_URL="<production-url>" npm run db:seed
   ```
6. Redeploy. Готово — магазинът и админ панелът работят на твоя `*.vercel.app` адрес (или custom домейн, добавен от Vercel → Domains).

## 3. Как да качваш нови продукти (клиентът може сам)

Админ панел → **Продукти → + Нов продукт**: име, категория, цени (EUR/BGN), цвят, материя, описание, линк към снимка, и таблица с редове размер/наличност (добавят се/премахват се динамично). Save → продуктът веднага се появява в магазина.

## 4. Как е събран каталогът (важно за клиента)

Продуктите са извлечени от публичните категорийни страници на topstyle.bg (без админ достъп до техния PrestaShop). Няколко неща да се знаят:

- **166 уникални продукта** от общо ≈476 в целия сайт бяха извлечени в тази първа партида (по ~20-24 на категория, от всичките 8 основни категории: тениски, якета, екипи, дънки/панталони, блузи, ризи, бански, комплекти). Останалите продукти могат да се доснемат по същия начин при нужда — просто кажи и ще довърша останалите страници.
- **Имената са пренаписани** — вместо оригиналното generic "тениска" / "бански" сега всеки продукт има описателно име (категория + кройка/стил + цвят), напр. *"Мъжка тениска – класическа кройка, в черен цвят"*.
- **Снимките са плейсхолдъри** — оригиналният сайт зарежда снимките си през JavaScript (lazy-load), затова при чисто извличане на HTML реалните снимки не бяха достъпни. Всеки продукт в момента показва цветен плейсхолдър вместо истинска снимка. Качването на истинските снимки е бърза задача през Admin → Продукти → Редактирай → поле "Снимка (URL)" (или ми дай снимките и ще ги заредя аз наведнъж).
- **Наличностите по размер са реалистично симулирани** (не са точното число от сайта — тази информация се показва само при hover/избор на конкретен вариант на живия сайт и изисква посещение на всяка продуктова страница поотделно). Клиентът трябва да прегледа и коригира точните количества преди истински старт на продажби.

## 5. CRO ъпдейти (по одита на Creative Ads)

Приложени промени по целия сайт за доверие и по-малко триене към поръчка:

- **Продуктова страница**: trust strip под "Добави в количката" (наложен платеж, преглед преди плащане, лесна замяна, връщане до 14 дни), sticky CTA лента в долната част на екрана на мобилни устройства, линк "Как да избера размер?" с кратък съвет, съобщение за последни бройки при ниска наличност.
- **Начало**: по-силно value proposition в hero секцията + ред с доверителни точки (наложен платеж, лесна замяна, връщане до 14 дни).
- **Категорийна страница**: бадж "Топ продукт" (ръчно от админ — виж по-долу) и бадж "Нов" (автоматично, по дата на добавяне до 14 дни), в допълнение на съществуващите "Изчерпан"/"Последни бройки" и размерите наличност на всяка карта.
- **Количка**: доверителен ред над бутона за поръчка.
- **Чекаут**: разделен визуално на стъпки с progress индикатор (Количка → Доставка → Плащане → Готово), избор на доставка като визуални карти (Еконт — до офис / Спиди — до адрес), постоянно резюме на поръчката със снимки на артикулите, доверителен ред до финалния бутон.
- **Админ**: нов чекбокс "Топ продукт" във формата на продукт — маркирай ръчно реалните бестселъри (не измисляме продажби, за да няма подвеждащи баджове).

**Важно — попълни истински данни преди пускане в експлоатация:**

Файл `src/lib/trust-config.ts` съдържа три полета, които съзнателно са оставени празни, за да не показваме измислени числа на клиенти:

- `sameDayCutoffTime` — часът, до който поръчките се изпращат същия ден (напр. `"16:00"`). Ако полето е празно, съобщението за спешност просто не се показва.
- `customersServedText` / `yearsInBusinessText` — реален брой клиенти / години на пазара за "authority" съобщението на началната страница.

Докладът предлагаше и showing на рейтинг ("★★★★★ 4.9/5 от клиенти") — съзнателно **не** е добавен, защото засега няма реални ревюта. Кажи ми, когато имате истински ревюта (Google/Facebook/Trustpilot), и ще го вградя.

A/B тестове и GA4/Clarity проследяване от доклада не са включени в тази ъпдейт — изискват свързване на вашите tracking акаунти; кажете ми когато искате да ги вържем.

## 6. Клиентски профили (вход/регистрация)

По подобие на ozone.bg, преди чекаут клиентът вижда избор: вход/регистрация с имейл+парола, или "Продължи без регистрация" (гост checkout). Избрахме **незадължителна** регистрация — CRO одитът изрично препоръчва гост checkout, защото задължителната регистрация отблъсква поръчки; ozone.bg скрийншотът показваше задължителен вариант, но той противоречи на препоръката, затова направихме избор вместо принуда.

- **Facebook/Google/Apple вход** не са включени — изискват реални OAuth приложения от съответните платформи (Facebook Developers, Google Cloud Console, Apple Developer), които трябва да създадете и да ми дадете Client ID/Secret. Кажете ми, когато имате тези данни, и ще ги вържа.
- **"Запомни ме"** е чекнато по подразбиране при вход — сесията трае 90 дни, така че връщащ се клиент остава влязъл автоматично, без да пази паролата в браузъра си (по-сигурно от буквално запомняне на паролата).
- Клиент → **Моят профил** (линк в горното меню) показва данните му и историята на поръчките му.
- Гост поръчка с имейл, който по-късно бъде регистриран, автоматично се "прикача" към новия профил (поръчката вече ще се вижда в профила).

## 7. Ревюта на продукти

Всеки продукт вече може да има ревюта от клиенти — звезден рейтинг + брой ревюта се показва под снимката както в категорийната страница, така и на продуктовата страница (плюс пълен списък с коментари под описанието). Ревютата **се управляват само от админа** (Продукти → Редактирай → секция "Ревюта на продукта" — добавяш име, оценка 1-5 и коментар, или трием съществуващо).

Съзнателно няма автоматично генерирани или примерни ревюта — рейтинг се показва само за продукт, който вече има поне едно реално вписано ревю. Добавяй само истински отзиви от клиенти.

## Структура на проекта

```

src/app/(store)/             витрина (начало, категория, продукт, количка)
src/app/admin/                админ панел (login + защитен (dashboard) с sidebar)
src/app/api/checkout/         API route за завършване на поръчка
src/components/               споделени UI компоненти
src/lib/                      db клиент, auth (сесии), форматиране на цени
```
