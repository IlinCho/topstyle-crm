# TopStyle.bg — PHP версия (за обикновен хостинг като Jump.bg)

Това е пълно пренаписване на сайта на чист PHP + MySQL — без Node.js, без build стъпка,
без Composer зависимости. Може да се качи с обикновен FTP/File Manager на почти всеки
cPanel хостинг, включително Jump.bg, независимо каква версия на Node.js поддържат
(въпросът изобщо отпада, защото не се използва Node).

Съдържа всичко от Next.js версията: категории с подкатегории, продуктови страници с
избор на размер, Smart Scarcity съобщения на база реална наличност, "уведоми ме при
наличност" форма, отзиви/рейтинги, количка, 4-стъпков чекаут с progress bar, клиентски
акаунти, пълен админ панел (продукти/категории/поръчки/отзиви/известия), и rate limiting
на входа за админ и клиенти.

## 1. Какво трябва в cPanel

Почти всеки cPanel план го има по подразбиране:
- PHP 7.4 или по-нов (проверява се в cPanel → "Select PHP Version" / "MultiPHP Manager")
- Разширението **PDO MySQL** трябва да е включено (по подразбиране е, в същия екран)
- Достъп до **MySQL Databases** и **phpMyAdmin**
- Достъп до **File Manager** или FTP

Няма изискване за конкретна версия на Node.js — тя изобщо не участва.

## 2. Създай базата данни

1. cPanel → **MySQL Databases** → създай нова база (напр. `jumpuser_topstyle`)
2. Създай MySQL потребител и парола, и го добави към базата с **ALL PRIVILEGES**
3. cPanel → **phpMyAdmin** → отвори новата база → таб **Import** → качи `schema.sql`
   от тази папка → Go

Това създава всички таблици и добавя един администраторски акаунт:
- Имейл: `admin@topstyle.bg`
- Парола: `ChangeMe123!`

**Смени тази парола веднага след първия вход** — засега няма "забравена парола" поток,
така че ако я загубиш, ще трябва ръчно да генерираш нов bcrypt хеш и да го смениш през
phpMyAdmin.

### Качи текущите продукти

`schema.sql` създава само празни таблици — продуктите трябва да се качат отделно, за
да отразяват това, което наистина е в Next.js админа В МОМЕНТА (включително всеки
продукт, добавен след първоначалната миграция от PrestaShop):

1. На своя компютър отвори Terminal и пусни:
   ```
   cd "/Users/ilinanri/Claude/Topstyle New CRM"
   node scripts/prestashop-import/export-to-mysql.mjs
   ```
   Това създава файл `php-site/mysql-data-export.sql` с точна снимка на текущия каталог.
2. phpMyAdmin → същата база → Import → качи `php-site/mysql-data-export.sql` → Go
3. (По избор) Import → качи и `scripts/prestashop-import/mysql-customers.sql` от тази
   папка — списъкът със стари клиенти за разпознаване "Стар клиент" при поръчка.

Старите файлове `mysql-import.sql`/`mysql-categories.sql`/`mysql-images.sql`/
`mysql-fix-vat.sql` вече не са нужни за нов деплой — бяха еднократната миграция от
PrestaShop и вече напълно се покриват от прясната справка по-горе. Пусни
`export-to-mysql.mjs` пак и импортирай резултата всеки път, когато искаш MySQL версията
да настигне последните промени от Next.js админа (напр. точно преди реалния cutover).

## 3. Качи файловете

Качи **цялото съдържание** на тази папка (`php-site/`) в директорията, от която се
сервира твоят домейн (обикновено `public_html/`, или `public_html/topstyle/` ако е
поддиректория). Структурата на файловете трябва да остане същата — не преименувай папки.

## 4. Настрой `config.php`

Отвори `config.php` и попълни истинските стойности:

```php
define('DB_HOST', 'localhost');
define('DB_NAME', 'jumpuser_topstyle');   // твоето реално име на база
define('DB_USER', 'jumpuser_admin');      // твоят реален потребител
define('DB_PASS', '...');                 // твоята реална парола

define('SESSION_SECRET', '...');          // генерирай дълъг случаен низ
```

За `SESSION_SECRET` можеш да поискаш от Claude да генерира случаен низ, или сам да
пуснеш `openssl rand -hex 32` ако имаш достъп до терминал. Никога не оставяй плейсхолдъра.

## 5. Качи снимки

`assets/logo.png` и `assets/hero.jpg` вече са част от папката (копирани от Next.js
версията) — няма нужда да ги добавяш сам.

Все още липсва `assets/placeholder.jpg` — резервна снимка, ако продукт няма качена
снимка. Ако липсва, страниците пак ще се показват нормално — просто ще има счупена
икона на изображение вместо снимка за такъв продукт (рядък случай, тъй като реалните
продукти вече имат качени снимки).

## 6. Пусни HTTPS

cPanel → **SSL/TLS Status** → включи **AutoSSL** (безплатен Let's Encrypt сертификат).
Сесийните "бисквитки" за админ и клиентски логин са маркирани `secure` автоматично
когато сайтът върви по HTTPS — важно е SSL да е активен преди да пуснеш реален трафик
с клиентски данни.

## 7. Тествай

1. Отвори `https://твоя-домейн/index.php` — трябва да видиш началната страница
   (ще е празна, защото няма продукти още)
2. Отиди на `https://твоя-домейн/admin/login.php` и влез с админ акаунта
3. Създай поне 1-2 категории (`/admin/categories.php`)
4. Създай продукт с размери/наличност (`/admin/product-form.php`)
5. Провери целия път: начало → категория → продукт → добави в количка → чекаут → поръчка
6. Смени админ паролата веднага след първия вход — има вградена страница за това
   (Админ → "Смени парола", `/admin/change-password.php`), не се налага ръчна работа
   през phpMyAdmin.

## Какво е различно спрямо Next.js версията

- Поръчките пращат имейли (потвърждение до клиента + известие до теб при нова
  поръчка) през вградената PHP `mail()` функция — без нужда от външна услуга.
  Доставимостта им зависи от SPF/DKIM записите на реалния домейн, така че реши се
  колко добре пристигат чак след като домейнът вече сочи към този хостинг.
- Няма автоматична оптимизация/resize на снимки — очаква се готови URL адреси.
- Всяка страница чете директно от базата при всяко зареждане (без клиентско кеширане
  като в Next.js версията), затова наличностите винаги са "на живо" без нужда от
  отделен API endpoint.
- Admin достъпът е защитен централно през `includes/admin-header.php`, което всяка
  админ страница включва — така е физически невъзможно бъдеща страница да "забрави"
  проверката за сесия (точно това беше проблемът, който открихме и оправихме в
  Next.js версията).
